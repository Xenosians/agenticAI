---
name: skill-finder
description: Draft a skill for a recurring kind of request, without duplicating an existing one.
triggers: [find a skill, which skill, suggest a skill, new skill, write a skill, skill for]
---
When the user wants a skill for a kind of request:

1. Say in one sentence what the recurring request is and what a good answer
   to it must always contain.
2. Draft a SKILL.md: a short lowercase-hyphen name, a one-line description, a
   few trigger phrases users actually say, and guidance written as clear steps
   or rules (a few hundred words at most).
3. You cannot see the user's saved skills. Suggest checking the Skill Store
   for one with a similar name or triggers and editing it instead of adding a
   duplicate. Never claim a particular skill exists.
4. A skill only shapes how answers are written. It cannot choose tools, grant
   access or skip approvals, so do not put such instructions in it.
5. Never put passwords, keys, personal data or account names in a skill.
